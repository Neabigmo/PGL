# PGL

PGL (persistent Gauss-linking operator) is a fixed, label-free representation of
protein-ligand interfaces. Protein Cα atoms and ligand heavy atoms form a contact
graph; protein-ligand pairs are oriented segments, and a regularized Gauss pairing
between segments gives a weighted coupling. Normalising that coupling into a
positive-definite metric on the edge space and inserting it into the persistent edge
Laplacian makes the operator's positive spectrum respond to how contacts are arranged.
The readout is deliberately compact: 287 contact-token features per complex (15
chemistry channels, 114 token statistics and 158 all-atom contact descriptors) are
concatenated with frozen Uni-Mol (512) and SaProt (480) context embeddings and mapped
to pK by XGBoost, 1,279 features in total. Contact-token extraction runs on CPU and
never reads affinity labels.

## Release

Version **1.0.0** (`v1.0.0`) is the model reported in the manuscript. It has one
feature schema (287 contact tokens, 512 ligand context, 480 protein context), one
XGBoost configuration and three seeds (20261022, 20261023, 20261024).

`src/pgl/release.json` is the single release record: model identifier and checkpoint
layout, feature block order and dimensions, sample-list hashes, metric definitions,
and the released result tables. `release/schema.json` lists the 1,279 feature names in
column order and hashes them; a checkpoint can be bound to this schema and is checked
against it on load. Released benchmark tables, figure source data, split identifier
lists, an example prediction file and a small end-to-end regression fixture are in
`release/`. The tests cross-check the code, the release record and the released files,
so the repository describes the same model as the paper.

| benchmark | n | RMSE (3 seeds) | protocol |
|---|---|---|---|
| CASF-2016 | 285 | 1.301 ± 0.017 | frozen readout trained on PDBbind-2016 development |
| BDB2020+ | 115 | 1.040 ± 0.015 | frozen readout, external confirmation |
| LP-PDBBind | 2138 | 1.636 ± 0.031 | retrained on the official training split |
| PDBbind-2013 | 184 | 1.575 ± 0.029 | retrained on the reconstructed training split |

## Installation

```bash
python -m pip install -e .
# with test and lint tools
python -m pip install -e ".[dev]"
```

Requires Python 3.10 or newer, NumPy, SciPy, scikit-learn, RDKit and XGBoost. The
contact-token operator, context assembly and the XGBoost readout run on CPU. The
manuscript pipeline also needs the pretrained encoders described below, which are
provided outside this repository.

## CPU operator + readout demo

The repository bundles a small synthetic dataset in `examples/toy` (60 toy complexes
and fixed demo labels, generated by `examples/make_toy.py`). It exercises the complete
CPU path — contact tokens, context assembly, schema check, readout training and
prediction — in about 30 seconds and carries no scientific claim. The reproduction
section below is the path to the paper's numbers.

```bash
pgl features --manifest examples/toy/manifest.csv --out tokens.npz
pgl train --features tokens.npz --labels examples/toy/labels.csv --out readout --threads 4
pgl predict --model readout --features tokens.npz --out predictions.csv
```

`pgl features` writes one 287-dimensional vector per complex. `pgl train` fits the
XGBoost readout with the predeclared hyper-parameters and prints the training metrics.
`pgl predict` writes `sample_id,y_pred` rows (exact values depend on the XGBoost build
and thread count):

```csv
sample_id,y_pred
toy01,5.669534
toy02,5.642188
```

The same steps through the Python API:

```python
from pgl import contact_features

result = contact_features("examples/toy/complexes/toy01_protein.pdb",
                          "examples/toy/complexes/toy01_ligand.sdf")
print(result.vector.shape)          # (287,)
print(result.counts["n_contacts"])  # protein-ligand contacts at the central window
```

Frozen context embeddings are attached by identifier, in the order contact tokens,
Uni-Mol, SaProt:

```bash
pgl context --tokens tokens.npz --unimol unimol.npz --saprot saprot.npz --out features.npz
```

Each context archive stores `ids` and `vectors` (`512` or `480` columns). Rows without
a context block stay NaN and are handled by the tree model; no value is imputed.

## Manuscript 1,279-D pipeline

The manuscript model is the concatenation of three blocks in a fixed order:
contact tokens (287), Uni-Mol ligand context (512), SaProt protein context (480):
1,279 columns, followed by the XGBoost readout. This repository implements the
contact-token operator, the context file interface and the readout. The two context
blocks are produced outside the repository by scripts that run the pretrained
encoders; `pgl/context.py` only reads the resulting archives, aligns them by sample
identifier, checks the schema and concatenates the blocks.

* **Uni-Mol ligand context (512).** The external encoder runs Uni-Mol on the prepared
  ligand and returns one 512-dimensional representation per complex. The generation
  script owns input preparation, the chain/alternate-location conventions of the
  ligand file, truncation of unusually large ligands and the failure policy for
  structures the encoder cannot process; failures are reported in the coverage record
  rather than imputed here.
* **SaProt protein context (480).** The external encoder runs SaProt on the selected
  protein chain(s), pools the residue representations and writes one 480-dimensional
  vector per complex. Chain selection, pooling, handling of missing residues,
  truncation of long chains and the Foldseek/3Di cache (including cache-miss and
  encoder-failure handling) belong to that script, together with the decoder settings
  needed for the 3Di tokens.
* **Checkpoints.** A readout directory contains `readout.json` plus `config.json`
  (see `src/pgl/release.json` under `model`). `config.json` records the seed, the
  feature width and, when the checkpoint was fitted with a schema, the schema hash.

`pgl` therefore does not generate context embeddings itself, and it does not require
a GPU for the operator, context assembly or readout. Producing the two context blocks
is a separate, heavier step that depends on the encoder installations.

## Reproducing the paper's benchmarks

The paper reports four benchmarks. This section covers PGL's own benchmark path only;
the baselines in the comparison are not reproduced by this repository. The models for
CASF-2016 and BDB2020+ are trained once on the PDBbind-2016 development set and
applied unchanged; LP-PDBBind and PDBbind-2013 are retrained on their own training
splits. Every benchmark uses the same three seeds and the same readout.

The steps are feature extraction, context attachment, readout training (or loading
the released readout) and prediction. [docs/reproduction.md](docs/reproduction.md)
gives the exact commands, the expected directory layout and the mapping from figure
source data to result tables:

```bash
# 1. contact tokens, one archive per split
pgl features --manifest data/manifests/casf2016_test.csv --out work/casf_tokens.npz
# 2. attach frozen context
pgl context --tokens work/casf_tokens.npz \
    --unimol data/context/casf_unimol.npz --saprot data/context/casf_saprot.npz \
    --out work/casf_features.npz
# 3. predict with a fitted readout (one directory per seed)
pgl predict --model weights/pgl/seed20261022 --features work/casf_features.npz \
    --out work/casf_predictions_seed20261022.csv
```

Training uses the 3,758 PDBbind-2016 development rows that have both context blocks;
`release/splits/pdbbind2016_train3758.csv` is that list and
`pgl train --train-manifest` selects it. Inference keeps rows whose context is
missing and lets XGBoost route the NaN columns, which is why the evaluated cohorts can
be larger than the training cohort.

`release/splits/` lists the sample identifiers of every split with their SHA-256
hashes, so a locally prepared cohort can be checked against the released one.

BDB2020+ labels are pKa values from the same negative-log scale used elsewhere
(pKa = 9 − log10 K_nM = −log10 K_M); the benchmark differs from CASF-2016 in assay
source and cohort, not in the logarithmic unit. It is reported as a separate
benchmark and never pooled with the other datasets.

Protein-ligand structures, affinity labels and the frozen encoder embeddings are not
redistributed with this repository; they must be obtained from their providers
(PDBbind, CASF-2016, Uni-Mol, SaProt) under the respective terms.

## Repository layout

```
src/pgl/
  operator.py     contact topology, persistent operator, structure parsing
  features.py     287-dimensional contact-token representation
  contacts.py     all-atom contact block (158 features)
  context.py      context archive reader, id alignment and feature assembly
  schema.py       ordered 1,279-name feature schema and hash
  readout.py      XGBoost readout with optional schema binding
  metrics.py      RMSE, MAE, Pearson r, Spearman rho
  data.py         archive, label and id-list input/output
  release.py      loader for the release record
  release.json    release record: schema, sample lists, metrics, checkpoints
  cli.py          pgl features|context|train|predict|info
release/          released tables, figure source data, splits, schema, fixtures
docs/             algorithm, feature, API and reproduction notes
examples/         toy complexes and the demo data generator
tests/            operator, feature, context, schema, readout, release and CLI tests
legacy/           earlier internal readout, kept for reference only
```

## Tests

```bash
python -m pytest
```

The suite covers the operator identities, the metric bounds, the contact-token block,
context assembly, the feature schema and its use by the readout, determinism, the
release record and released data hashes, an end-to-end toy regression, and the three
quickstart commands. It runs on CPU and needs no network access.
