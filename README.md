# PGL

PGL (persistent Gauss-linking operator) is a fixed, label-free representation of
protein-ligand interfaces. Protein Cα atoms and ligand heavy atoms form a contact
graph; protein-ligand pairs are oriented segments, and a regularized Gauss pairing
between segments gives a weighted coupling. Normalising that coupling into a
positive-definite metric on the edge space and inserting it into the persistent edge
Laplacian makes the operator's positive spectrum respond to how contacts are arranged.
The readout is deliberately compact: 287 contact-token features per complex (15
chemistry channels, 114 token statistics and 158 all-atom contact descriptors) are
concatenated with frozen Uni-Mol (512) and SaProt (480) context embeddings and mapped
to pK by XGBoost, 1,279 features in total. Feature extraction runs on CPU and never
reads affinity labels.

## Release

Version **1.0.0** (`v1.0.0`) is the model reported in the manuscript. It has one
feature schema (287 contact tokens, 512 ligand context, 480 protein context), one
XGBoost configuration and three seeds (20261022, 20261023, 20261024).

`src/pgl/release.json` is the single release record: model identifier and checkpoint
layout, feature block order and dimensions, sample-list hashes, metric definitions,
and the released result tables. Released benchmark tables, the Fig. 2 source data and
an example prediction file are in `release/`. The tests cross-check the code, the
release record and the released files, so the repository describes the same model as
the paper.

| benchmark | n | RMSE (3 seeds) | protocol |
|---|---|---|---|
| CASF-2016 | 285 | 1.301 ± 0.017 | frozen readout trained on PDBbind-2016 development |
| BDB2020+ | 115 | 1.040 ± 0.015 | frozen readout, external confirmation |
| LP-PDBBind | 2138 | 1.636 ± 0.031 | retrained on the official training split |
| PDBbind-2013 | 184 | 1.575 ± 0.029 | retrained on the reconstructed training split |

## Installation

```bash
python -m pip install -e .
# with test and lint tools
python -m pip install -e ".[dev]"
```

Requires Python 3.10 or newer, NumPy, SciPy, RDKit and XGBoost. No GPU is needed.

## Quick start

The repository bundles a small synthetic dataset in `examples/toy` (60 toy complexes
and fixed demo labels, generated by `examples/make_toy.py`). It exercises the complete
pipeline on CPU in about 30 seconds and carries no scientific claim; the reproduction
section below is the path to the paper's numbers.

```bash
pgl features --manifest examples/toy/manifest.csv --out tokens.npz
pgl train --features tokens.npz --labels examples/toy/labels.csv --out readout --threads 4
pgl predict --model readout --features tokens.npz --out predictions.csv
```

`pgl features` writes one 287-dimensional vector per complex. `pgl train` fits the
XGBoost readout with the predeclared hyper-parameters and prints the training metrics.
`pgl predict` writes `sample_id,y_pred` rows (exact values depend on the XGBoost build
and thread count):

```csv
sample_id,y_pred
toy01,5.669534
toy02,5.642188
```

The same steps through the Python API:

```python
from pgl import contact_features, XGBReadout

result = contact_features("examples/toy/complexes/toy01_protein.pdb",
                          "examples/toy/complexes/toy01_ligand.sdf")
print(result.vector.shape)          # (287,)
print(result.counts["n_contacts"])  # protein-ligand contacts at the central window
```

Frozen context embeddings are attached by identifier, in the order contact tokens,
Uni-Mol, SaProt:

```bash
pgl context --tokens tokens.npz --unimol unimol.npz --saprot saprot.npz --out features.npz
```

Each context archive stores `ids` and `vectors` (`512` or `480` columns). Rows without
a context block stay NaN and are handled by the tree model; no value is imputed.

## Reproducing the paper's benchmarks

The paper reports four benchmarks. The models for CASF-2016 and BDB2020+ are trained
once on the PDBbind-2016 development set and applied unchanged; LP-PDBBind and
PDBbind-2013 are retrained on their own training splits. Every benchmark uses the same
three seeds and the same readout.

The steps are feature extraction, context attachment, readout training (or loading the
released readout) and prediction. [docs/reproduction.md](docs/reproduction.md) gives
the exact commands and the expected directory layout:

```bash
# 1. contact tokens, one archive per split
pgl features --manifest data/manifests/casf2016_test.csv --out work/casf_tokens.npz
# 2. attach frozen context
pgl context --tokens work/casf_tokens.npz \
    --unimol data/context/casf_unimol.npz --saprot data/context/casf_saprot.npz \
    --out work/casf_features.npz
# 3. predict with a fitted readout (one directory per seed)
pgl predict --model weights/pgl/seed20261022 --features work/casf_features.npz \
    --out work/casf_predictions_seed20261022.csv
```

`release/splits/` lists the sample identifiers of every split with their SHA-256
hashes, so a locally prepared cohort can be checked against the released one.

Protein-ligand structures, affinity labels and the frozen encoder embeddings are not
redistributed with this repository; they must be obtained from their providers
(PDBbind, CASF-2016, Uni-Mol, SaProt) under the respective terms.

## Repository layout

```
src/pgl/
  operator.py     contact topology, persistent operator, structure parsing
  features.py     287-dimensional contact-token representation
  contacts.py     all-atom contact block (158 features)
  context.py      frozen 512/480 embedding interface and feature assembly
  readout.py      XGBoost readout
  metrics.py      RMSE, MAE, Pearson r, Spearman rho
  data.py         archive and label input/output
  release.py      loader for the release record
  release.json    release record: schema, sample lists, metrics, checkpoints
  cli.py          pgl features|context|train|predict|info
release/          released tables, figure source data, sample lists, predictions
docs/             algorithm, feature, API and reproduction notes
examples/         toy complexes and the quickstart data generator
tests/            operator, feature, context, readout, release and CLI tests
legacy/           earlier internal readout, kept for reference only
```

## Tests

```bash
python -m pytest
```

The suite covers the operator identities, the metric bounds, the contact-token block,
context assembly, readout fitting and saving, determinism, the release record and
released data files, and the three quickstart commands. It runs on CPU in a few seconds
and needs no network access.
